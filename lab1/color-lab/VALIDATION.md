# Проверка формул

Все 40 юнит-тестов проходят. Тестируется `dist/colors.js`: этот же модуль
подключается к интерфейсу и встраивается в автономный HTML.

## Диапазоны и соглашения

- RGB — три конечных числа от 0 до 255; дробные значения разрешены.
- CMYK — четыре конечных процента от 0 до 100.
- HSV — H в градусах; S и V от 0 до 100%. H нормализуется по модулю 360.
- У серых цветов H не определён; сохраняется previousHue, по умолчанию 0°.
- При переводе RGB → CMYK выбирается канонический вариант с максимальным K.
- HEX принимает только #RRGGBB. Короткие записи и альфа не поддерживаются.
- HEX округляет каналы до целых; промежуточные расчёты не округляются.
- Преобразования предназначены для указанных диапазонов. Проверку ввода
  выполняет интерфейс; математический модуль не проверяет произвольные
  некорректные массивы и NaN.

## RGB и CMYK

Для r=R/255, g=G/255, b=B/255 обозначим q=max(r,g,b).

K=1−q; C=(q−r)/q; M=(q−g)/q; Y=(q−b)/q.
Если q=0, задаём C=M=Y=0, K=1 — без деления на ноль.
Это эквивалентно C=(1−r−K)/(1−K) и аналогичным формулам.
Запись через q уменьшает потерю точности при вычитании близких к единице чисел.

Обратно: r=(1−C)(1−K), g=(1−M)(1−K), b=(1−Y)(1−K).
Подставим C=(q−r)/q и K=1−q: (1−C)(1−K)=(r/q)q=r.
Так алгебраически проверяется обратимость для q>0; чёрный проверяется отдельно.
Код использует проценты, поэтому при обратном переходе делит их на 100.

CMYK — идеализированная учебная модель, а не преобразование для конкретной
печати. Разные CMYK-координаты могут давать одинаковый RGB. Обратимость
проверяется по цвету, а не обязательному восстановлению четырёх координат.
Печатные ICC-профили не реализованы.

## RGB и HSV

max=max(R,G,B), min=min(R,G,B), delta=max−min.
V=max/255; S=0 при max=0, иначе S=delta/max.
H вычисляется по сектору максимального канала и приводится к [0,360).
Обратное преобразование использует C=V*S,
X=C*(1−|((H/60) mod 2)−1|), m=V−C и шесть секторов тона.
Для вычислений S,V являются долями, для интерфейса — процентами.

Независимое сравнение: 260 RGB-примеров и 269 HSV-примеров со стандартной
библиотекой Python colorsys. Эталоны сохранены в tests/reference.json;
повторное создание: python3 tests/generate-reference.py.
Python задаёт H,S,V в долях; эталоны переводятся в градусы и проценты.

Источник: https://docs.python.org/3/library/colorsys.html
HEX: https://www.w3.org/TR/css-color-4/#hex-notation

## Исправленные погрешности

1. Убрано сравнение K>=1−1e−12: почти чёрный RGB мог ошибочно получать
   CMYK=(0,0,0,100). Теперь отдельно обрабатывается только точный чёрный.
2. Убрано delta>1e−12: почти серый цвет мог сохранить прошлый H вместо
   вычисленного тона. Случай отсутствия тона — только delta=0.
3. Парсер HEX проверяет тип входа перед обработкой строки.

## Покрытие

- Чёрный, белый, шесть основных/дополнительных цветов и оранжевый.
- Все 256 целых серых оттенков, сохранение H у серого.
- Границы и середины шести секторов H, 0°=360°, отрицательные углы.
- S=0, V=0, K=100%, неоднозначность CMYK, дробные координаты.
- Почти чёрный и почти серый: регрессионные тесты исправлений.
- HEX: формат, регистр, ведущие нули, округление, обратимость.
- 529 независимых эталонов Python colorsys.
- 10 000 RGB, 2 000 CMYK и 2 000 HSV с фиксированными начальными
  значениями генератора: результат воспроизводим при повторном запуске.
- Входные массивы не изменяются.

Обычный допуск — 1e−9 в единицах выходного канала; для обратного HSV —
1e−8; отдельные тесты используют допуск по размеру проверяемого эффекта.
Это покрытие формул, а не доказательство для каждого возможного числа.
IEEE-754 ограничивает точность, особенно для предельно малых значений.
Полная визуальная проверка в браузере в этой среде не выполнена.
